# Bantay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a deployed, mobile-first web app that checks a Philippine SMS for scam signals and explains the verdict in Taglish, with a deterministic engine making the decision and an LLM only writing the explanation.

**Architecture:** A pure TypeScript engine (`lib/engine`) extracts URLs and text signals, scores them, and returns a `Verdict`. A thin LLM layer receives a stripped `ExplanationInput` (never the message, URLs, or evidence) and returns a Taglish explanation, falling back to a template. A Next.js 16 App Router page renders verdict and explanation, with screenshot OCR done client-side.

**Tech Stack:** Next.js 16 (App Router), React 19, TypeScript (strict), Tailwind CSS v4, Vitest, Testing Library, Playwright, `tldts`, `tesseract.js`, `ai` + `@ai-sdk/groq`, `zod`, `lucide-react`.

**Spec:** `docs/superpowers/specs/2026-11-07-bantay-design.md`

## Global Constraints

- Next.js 16 App Router, TypeScript strict, Tailwind v4. Light "signal room" theme only (off-white paper, ink-black type, monospace labels).
- Everything under `lib/engine/` is pure: no network, no filesystem, no framework imports.
- The LLM receives `ExplanationInput` only — never raw message text, `urls`, or `Signal.evidence`.
- `safe` verdicts never call the LLM; they always use the template.
- Score thresholds: `0–24` safe, `25–59` suspicious, `60–100` scam; any `critical` signal floors the score at 60.
- Max input length: 1,000 characters.
- No database, no accounts, no logging of message content.
- Free tiers only: Vercel Hobby, Groq free tier.
- Product name: **Bantay**. UI copy is Taglish as specified in the spec §9.
- Every task ends with a commit. Commands assume repo root `/home/yvan/Projects/bantay`.

## Review Focus

- **Empty or whitespace-only input:** a reasonable person expects a calm "nothing to check" state, not a verdict card full of errors.
- **Malformed or partial URLs** (`http://`, `hxxp://`, trailing `)`, uppercase): parsing must never throw or crash the scan.
- **Mixed URLs** (one official, one not): the allowlist discount must not fire, and the malicious URL must still drive the verdict.
- **Very long input** (10,000 characters): the UI and API must reject or cap it cleanly, with no hang.
- **Unsafe or empty LLM output** (a URL, "click", a phone number, zero sentences): the validator must discard it and render the template instead.
